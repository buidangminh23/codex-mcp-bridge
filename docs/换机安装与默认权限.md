# 换机安装与默认权限

这份说明针对 Windows 上的本地 GPT ↔ Claude Desktop Code 协作。通信 MCP 和 Local Card Bridge Desktop 可以独立安装；前者负责交接，后者负责启动任务卡片和显示授权名单。它们不是云端项目上传工具，项目可以保留在本机。

本文是安装操作说明，不代表已在第二台电脑验收。请使用包含这些脚本的同一份已验收源码提交，另配卡片扩展 0.3.8；不要仅凭 npm 版本号假定已经包含本分支的改动。

## 1. 准备

安装并登录 Codex Desktop、Claude Desktop，准备 Node.js 22 或更新版本、Git，以及可用的 Codex CLI。源码放到固定目录，例如 `C:\Tools\GptClaudeBridge`，安装依赖。不要放临时目录。

保留源码提交号、扩展包版本及 SHA256。新机器不复制旧机器的登录缓存、会话 ID、回执或运行缓存。共享授权文件里有目录身份，也不能直接复制后当作新机器已授权；应按新路径重新接入。

## 2. 配置通信入口

需要的连接只有三项：

| 所在客户端 | 名称 | 用途 |
| --- | --- | --- |
| Codex | `claude-bridge` | 给 Claude 发消息、读取回执 |
| Codex | `codex-native-relay` | 把 Claude 的请求交给 Codex 桌面任务 |
| Claude Code，用户范围 | `codex-bridge` | 向 Codex 派发、报信和续等 |

Claude 这一项应在 **Code 的用户范围**，不要只装到普通聊天的共享 Desktop MCP 里，否则可能无法识别发信会话。CC Switch 如参与管理，也应保存相同入口，避免切换时恢复旧配置。

共享策略固定放在 `%USERPROFILE%\.config\GptClaudeBridge\projects.json`。先选一个专用测试目录，在源码根目录运行：

```powershell
node scripts/bridge-projects.mjs allow-project 'C:\Projects\BridgeTest'
```

在 Claude Code 用户级 MCP 配置中合并下面这个入口；将三个占位绝对路径换成新机器上的路径，保留其他连接和设置：

```json
{
  "mcpServers": {
    "codex-bridge": {
      "command": "C:/Tools/nodejs/node.exe",
      "args": ["C:/Tools/GptClaudeBridge/src/mcp-supervisor.mjs", "index.mjs"],
      "env": {
        "CODEX_BIN": "C:/Tools/Codex/codex.exe",
        "CODEX_BRIDGE_DESKTOP_TASKS": "1",
        "CODEX_BRIDGE_AUTOSTART": "0",
        "CODEX_BRIDGE_PROJECT_POLICY": "C:/Users/<user>/.config/GptClaudeBridge/projects.json",
        "CODEX_BRIDGE_ALLOWED_ROOTS": "C:/Projects/BridgeTest",
        "CODEX_BRIDGE_THREAD_POLICY": "roots",
        "CODEX_BRIDGE_APPROVAL_POLICY": "on-request",
        "CODEX_BRIDGE_SANDBOX": "workspace-write"
      }
    }
  }
}
```

`install-claude-code.mjs` 是已有入口的迁移/检查工具，不是从零安装器。先创建上述入口，再运行 `node scripts/install-claude-code.mjs --check`。已有机器需要迁移时，先退出 Claude 和配置管理器，再按[项目接入说明](项目接入说明.md)预览迁移计划。

Codex 一侧在源码目录配置同一策略，然后使用仓库安装器：

```powershell
$env:CODEX_BRIDGE_PROJECT_POLICY = Join-Path $env:USERPROFILE '.config\GptClaudeBridge\projects.json'
$env:CODEX_BRIDGE_DESKTOP_TASKS = '1'
node scripts/install-native-relay.mjs
node scripts/install-codex-mcp.mjs
```

若安装器找不到 Codex，先将 `CODEX_EXE` 设为新机器实际的 CLI 绝对路径。中继安装器可能创建初始中继任务，这是一次性安装动作。不要给安装器加跳过权限模式。Codex 官方提供 MCP 注册和配置机制，以上入口名及脚本是本项目的实现：[官方 MCP 说明](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

## 3. 默认权限：分开设置三层

| 层次 | 建议初始设置 | 是否每个对话重做 |
| --- | --- | --- |
| 工作区信任 | 明确接入具体项目；用 `prepare_bridge_project` / `inspect_bridge_project` | 通常按项目；工作树仍核验实际状态 |
| 通信与建卡名单 | 默认不允许所有项目；授权具体仓库或指定父目录，禁止记录优先 | 同仓库复用，不按对话授权 |
| 工具许可 | 只长期允许选定工具，保留其他正常审批 | 用户范围许可可复用；项目/管理策略仍可能覆盖 |

用户选择自动报信后，先预览再应用两项精确许可：

```powershell
node scripts/configure-message-automation.mjs
node scripts/configure-message-automation.mjs --apply --approve-message-automation
node scripts/configure-message-automation.mjs --check
```

脚本只允许 `send_to_codex_thread`、`wait_codex_reply`，并安装协作说明；不会自动授权新项目、放开 Shell 或关闭宿主审批。

如果也选择让助手管理建卡授权，可另行长期允许卡片扩展的以下 7 个精确工具：`authorize_project`、`revoke_project`、`desktop_bridge_info`、`list_projects`、`list_project_authorizations`、`inspect_desktop_card`、`verify_desktop_task`。本机是这样验收的。它们不是通信安装脚本自动添加的选项；应在实际 Code 用户设置里核对，不要把普通聊天的连接器许可当成 Code 已加载。

不要默认允许所有 MCP、任意命令、永久删除或清理工具。`start_desktop_card` 本机由正常自动模式处理；新机器若要求批准，按实际提示处理，不能宣称已由上述 7 项包含。`ready=true` 也不是工具审批已通过。

## 4. 安装可选卡片扩展

在 Claude Extensions 安装已验收的 MCPB。若同时安装通信桥，在源码目录运行 `node scripts/bridge-projects.mjs register-card-settings`，让原扩展设置页找到通信管理入口；然后在该页分别维护“建卡”和“通信”的项目/父目录。

只装其中一个也可以使用。通信未安装时，卡片功能应独立正常运行。查询 `desktop_bridge_info` 显示的实际存储路径；Windows 商店版的 AppData 视图可能不同。不要手动写 Claude 的私有设置文件来强行刷新页面。

配置连接后重新加载相应客户端，并在实际会话检查。需要后台卡片刷新时，可使用带 `--disable-backgrounding-occluded-windows` 和 `--disable-renderer-backgrounding` 的 Claude 快捷方式。这是本机的兼容措施，必须在新机器重测；普通刷新不等于带参数重新启动。无需 Remote Control。

## 5. 换机验收

在测试项目从 Code 侧栏加号建一个协作主会话。先核对真实 cwd，之后依次验证：

1. 两端状态、发信身份、目标项目授权正确。
2. GPT 发给 Claude，自动收回完整最终答复。
3. Claude 主动发给 GPT，自动收到答复；另测一次首次超时、同一回执续等，不能重复派发。
4. 在测试目录创建、读回、删除一个明确命名的测试文件。
5. 如使用卡片：分别启动 local / worktree，核对目录、父会话、分支、Remote Control 关闭；重复启动不新增会话。
6. 在测试项目撤销、恢复建卡授权，核对设置页与状态一致，通信授权不变；再做一轮普通任务，确认不是一次性成功。

有一步未完成就记录哪一步，不把“工具能看到”当成全通。预填链接的目录问题见[新会话目录核验](新会话目录核验.md)。日常任务只需要读[交接速查](日常交接速查.md)。

## 6. 升级、备份与清理

升级前记录源码版本、扩展 SHA256、共享策略和实际配置路径。备份配置及去重回执；不要将这些个人数据提交到公开仓库。升级后重复双向小任务和卡片核验。

归档会话不保证清理工作树。历史文件先移入带清单的归档目录，确认无依赖后再考虑删除；保留当前源码、运行版本、配置、回执和最近验收证据。新机器默认不继承旧机器的授权身份或未完成回执。
