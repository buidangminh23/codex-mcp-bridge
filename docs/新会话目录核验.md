# 新会话不要只看预填的项目名

Claude Desktop 的 `claude://code/new?folder=...` 链接在部分 Windows 版本上可能显示正确的项目，却把会话建在 `No folder` 临时目录。公开报告与本机现象一致，但本项目无法修补 Claude 客户端本身：

- [官方链接参数说明](https://support.claude.com/en/articles/14729294-open-claude-desktop-with-a-link)
- [同一目录重复打开变成 scratch workspace 的问题报告](https://github.com/anthropics/claude-code/issues/92210)

## 推荐的首次接入流程

1. 用户要求新建协作会话时，由用户或已获授权的 Computer Use 在 **Code 侧栏的目标项目旁点加号**。不要把原有会话当作新会话。
2. 等待项目和分支加载完成，确认 Local、正确项目、预期分支与 worktree 选择。Git 分支还是 `—` 时不要马上发送。非 Git 项目不要求分支。
3. 第一条只做准备检查：报告实际 cwd、会话 ID、Git 根目录（如有）和 Remote Control 状态，不改文件、不执行生产任务。
4. 用 `list_claude_sessions` 核对新会话的原生 task ID、CLI session ID、账号和真实 cwd。匹配成功后，固定 `expectedCwd` 与 `expectedTaskId`，经 MCP 派发正式任务。
5. 后续通信复用已核对的主会话，不必每次打开新会话或切换窗口。任务卡片启动仍需要在 Claude 内显示其所属主会话。

## 已经用过预填链接时

打开链接不等于会话创建成功。保留原 requestId，读取原回执，不重复发送。`promptSubmitted=false` 和 `submissionStatus=not_observed` 只代表桥没有核验到提交，**不能证明 Claude 没收到**：错误目录可能不在授权查询范围内。

先查看 Desktop 的现有会话。若发现 No folder，停止派发正式工作；不要扩大目录授权来强行匹配。待用户明确取消旧创建请求、确认已有任务状态后，再从目标项目入口建立新会话。不得以此绕过任何宿主审批拒绝。

`awaiting_project_confirmation` 代表已经观察到提交但实际目录不对；`created` 才代表新原生会话、账号、进程、初始消息与项目目录均已匹配。重复或模糊匹配不会自动挑选会话。

这是对客户端问题的规避流程，不应标记为“预填链接 bug 已修复”。
