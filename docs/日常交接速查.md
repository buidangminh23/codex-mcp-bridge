# GPT ↔ Claude 日常交接速查

## 一次性准备

安装通信 MCP；需要自动启动 Claude 任务卡片时，再安装 Local Card Bridge Desktop。两者可以独立使用。

换电脑或重装时，先按[换机安装与默认权限](换机安装与默认权限.md)设置；日常任务不用重复安装。

把项目或父目录加入通信授权；需要建卡时另加建卡授权。Claude 工作区信任、项目名单、工具调用许可是三件事，不能互相替代。用 `inspect_bridge_project` 和两边的状态工具检查实际会话，不以“工具出现了”作为接通依据。

首次建立 Claude 协作主会话，优先从 Code 侧栏目标项目旁的加号进入，先只读核对真实目录，再开始正式交接。详见[新会话目录核验](新会话目录核验.md)。一个项目可复用一个协作主会话，不必每个小任务重新创建。

## 日常流程

1. **找准主会话**：核对项目目录、标题、原生 task ID。GPT 使用 `list_claude_sessions`，之后发送时带明确的 `expectedCwd` 和 `expectedTaskId`。
2. **派任务**：通过通信 MCP 发清楚目标、允许修改的文件、限制和验收条件。已有任务继续原会话；确需独立侧栏任务时才建卡。
3. **启动子任务**：Claude 创建原生任务卡片，保留 parent session ID、task ID、标题和 local/worktree 模式。让 Claude 内显示对应主会话，调用 `start_desktop_card`，再核对子会话实际目录、父子关系、分支和 Remote Control 关闭。
4. **回传结果**：Claude 用通信 MCP 主动报进展、请求协助或派任务给 GPT。消息发送成功不等于任务完成；要收到对应回合的最终答复。
5. **超时继续等**：Claude→GPT 已接受但超时，用同一 `deliveryId` 调 `wait_codex_reply`；GPT→Claude 保留原 `msgId` 查询回执。结果不确定时不要重发，也不要更换 ID 重建卡片。

## 两种执行位置

- local：子任务使用主会话的工作目录；多个任务可能碰到同一批文件，需要分配好修改范围。
- worktree：独立目录和工作分支；仍属于同一 Git 仓库。只切分支不会把现有工作目录搬到别处。

## 权限和故障

建卡撤销只禁止该仓库启动卡片，不等于撤销通信。通信撤销也不应改变建卡名单。名单变更后等原生设置保存完成，再核对结果；0.3.8 修复了状态查询继续显示旧来源标签的问题。

“项目未授权”、Claude 工具审批拒绝、发送方身份识别失败、网络认证故障应分别报告。遇到宿主拒绝，保留原错误并走正常审批，不通过换入口或伪装用户重试。

通信不需要切换 Claude 的当前对话；点任务卡片则需要让对应主会话在 Claude 内显示。后台刷新依赖客户端行为，本机用带后台参数的快捷方式启动 Claude。不要开启 Remote Control。

归档会话不保证清理 worktree 或分支。清理前检查运行状态、未提交修改和独有提交，保留授权记录与去重回执。
